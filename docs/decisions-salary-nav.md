## 已确定（用户拍板）

- **T1 「日薪改月工资」= 包月制**。月工资是一个固定数，出勤天数不改变这笔钱；加班 / 双倍工资那天另加一笔。
  - 理由：倒班行业月薪通常是固定数，出勤天数不决定这笔钱；现引擎按「日薪 × 出勤天」累加，算出的「月应发」会随排班变，跟 HR 给的月薪对不上 —— 这大概率就是改月工资的根因。
  - **附带收益**：历史月份的应发不再随「现在改了班表」而变化。现引擎的口径是改了排班、历史月份跟着变；包月制下这条自动消失，那是更对的行为。
- **T2 抬到底栏 = 真的高频**。用户答「我经常看」，不是「嫌藏得深」。前提成立：它值一格全局导航位。
- **T3 定位 = 记账本，用户接受**。包月制下「应发」是用户填的数，App 不再按排班算钱。
- **T4 补助：合进月薪，删掉这个字段**。月薪 = 到手的全部固定部分。包月制的意义就是减少用户要手动维护的字段；补助单列只多一个要维护的数字。
  - 连带：`PayrollConfig` 从 `{dailyWage, dailySubsidy}` 收成 `{monthlyWage}` 一个字段；`isUnset` 的判据从「两个都是 0」变成「月薪是 0」。
- **T5 单日加项：留，语义改成「这天额外加多少」**。原来「替换固定日薪」在包月制下没基可换（月薪除以天不是真实单价）；加班工资是真实发生的，全靠人手记实发的话统计页就没有任何计算价值。
  - 连带：`payroll_day_wage_rows` 里存的金额语义从「替换值」变成「加项」，**不能自动迁移**（老数据按「替换」口径填的，留下来会算飞）。
- **T6 老数据：清空重填**。日薪 × 任何天数都是猜，猜错了用户看到「应发」多出一笔会以为 App 算错钱；清空重填多一步，但一步到底。单日自定义一并清。
- **T7 第 5 个 tab 插到「待办」与「我的」之间**（索引 3）。底栏惯例「业务功能 → 个人设置」，薪资属业务，「我的」保持末位。
- **T8 tab 标签 = 「薪资」**。与 App 现有文案「统计与薪资」同源，指向钱本身；不叫「统计」（日历页本身就是统计，职责重叠）。
  - 图标沿用 `Icons.account_balance_wallet_outlined`（「我的」页那个入口现用的）—— 与底栏另外四个同为 outlined，风格一致。
- **T9 「我的」页那个入口删掉，连「统计与薪资」那一节一起删**。单入口；那一节只有这一条，删后不空。

## 自己定的（用户未单独拍板，理由充分，不同意可改）

- **T10 月薪的计入判据：这个月至少有一天出勤，月薪才全额计入**。
  - 判据：`MonthPay.days.isNotEmpty`（复用现有引擎「那天有非休班次」的判据，不新增口径）。
  - 理由：包月制 = 月薪是月度常量，不随出勤天变；但这个月**完全没排班**（没段覆盖 / 空白表 / 全休）时，App 里凭空多出一个月薪数会跟用户认知对不上（他没上班，HR 也不会发）。
  - 上 3 天班：月薪仍全额。这才是包月制。
  - 与现有行为一致：`days` 为空时 `total` 本为 0，包月制下不注入月薪即保持一致。

## 已查明（自己查的，不问用户）

- **5 tab 的窄屏宽度撑得住**：胶囊最大 440dp（`kNavCapsuleMaxWidth`），窄屏不生效，实际宽 = 可用宽 − 2×24dp outerPad。320dp 屏胶囊 272dp、**每格 54.4dp**；图标 24dp + 2 字标签（约 20–24dp）仍有 10dp 以上余量。360dp 屏每格 64.8dp。
  - 但**工装必须补 5 tab 的窄屏矩阵**（320/360 × 4 档字号），否则液态档滑块的胶囊形状 / 图标扭曲在 5 格里会无声失效。
- `profile_screen.dart:248-260` 那个 `SectionHeading(L10n.sectionStats)` 节**只有 StatsScreen 一条**，删入口 → 连节一起删，「我的」页不空。

## 本版新增四条（拷打完成）

- **N1 农历开关**。设置页加一个开关，控制农历显示。
  - 范围：**App 日历页 + 桌面小组件都跟**（用户选，理由：一致性）。
  - 语义：关掉的是「农历日」，**法定节假日名保留**（国庆节红字还在）。所以判据要拆开：现在 `LunarInfo.cellLabel` 是「大节日 → 节气 → 农历日」三选一，得拆成「节日/节气」与「农历日」两段，开关只管后半段。
  - 连带：桌面小组件快照要重推；桌面小组件的位图也要跟着重烘（`widget_snapshot.dart` 那两处）。

- **N2 云备份「连不上服务器」（bug）**。
  - 先定性：项目里的云备份是 **WebDAV**（`webdav_sync.dart` / `webdav_sync_screen.dart`），不是自研服务器。所以「连不上」是 WebDAV 连接失败，不是服务器宕机。
  - **待用户提供报错文案**才能定位。常见成因：域名解析失败、证书链不全、公司代理、IPv6 未开、路径错（末尾多一个斜杠 / 少）、WebDAV 服务本身拒绝。
  - 定位后可能只是把错误信息写清楚（现在可能只报「连接失败」，用户看不出具体是什么错）。

- **N3 排班多选：同一天多个班次，分时段上**。
  - 场景：用户选了「分时段：上完回家再回来上」—— 两个独立班次，各自有起止时间，中间休息。
  - **本轮最大一块改动**（引擎级）：
    - `shiftOn(day)` 从返回 `ShiftClass?` 改成返回 `List<ShiftClass>`
    - `ShiftCycleRows`（周期序列）要支持一个位置多个班次下标（现在是一个位置一个下标）
    - 按天调班 `ShiftDayOverrides` 主键 `{scheduleId, day}` → 单班次，要改成支持多班次
    - 冲突检测 `crewClashes` 要按「同一天同时段两个班组」判（不再是「同一天同一个班」）
    - `ShiftClassAlarms` 闹钟：两个班次的闹钟都排
    - 编辑器 UI：周期设置那一段改成多选
  - **硬约束**：日历格子从三行变四行（多班次时）。已知风险：320×640 @ 特大字号下日历网格之前就会滚（v0.11.13），四行会更严重。需工装验证。

- **N4 日历时间段替换简称**。
  - 格子中位胶囊：「早 / 午 / 夜」→「0-2 / 2-4 / 4-6」（数据本就有：`startMinute` / `endMinute`）。
  - 跨天班次显示「22-06」，**不写「次日」**（用户选），靠颜色区分。
  - 连带：桌面小组件的班次胶囊也改（现在也画 `shortLabel`）；信息卡那行「本月 早 12 · 午 8」跟不跟着改待定（它现在按 `shortLabel` 累加天数，改时间段语义会变）。

## 实施方案（方案 B：分层交付）

选 B 的理由：**第一层是纯 Dart 单测，不用出图不用装 App，跑完就能确认「包月制算得对」这个唯一不可回滚点** —— 老数据清空了就是清空了，引擎口径错了后面 UI 做得再漂亮也白搭。串行与并行都把这点埋在最后，风险太晚暴露。

1. **数据与引擎**（~10 项）：schema v13→v14 迁移 + fixture 补表 + `payroll.dart` 引擎重写 + `app_repository.dart` 读写改造 + `payroll_test.dart` 全量重写
