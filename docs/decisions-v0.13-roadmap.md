## 已确定

### #2 薪资

- **D1 撤销上版 T1「月薪=全局配置一个固定数」**。改成「**逐月灵活填**」：月薪不再是 `PayrollConfig` 里的字段，而是每月一条可编辑记录（因为用户「每个月可能月薪都不一样」）。
- **D2 加项快捷按钮**：日薪按日出勤加项增加「100」快捷按钮（点一下填 100，不是默认值 100）。
- **D3 发薪记录多条**：同一个月可以记录多条实发记录（比如月中一次、月底一次）。

### #1 卡顿

- **D4 定性为回归 bug**（不是新体验目标）：「上个版本还没那么卡」。
- 现象：切换页面时先卡顿一下，然后正常。「只要切换页面就卡顿」——**任何切换都卡**（不局限于特定页面）。
- **D5 具体症状**：用户认同时轮拷打的 a+b+c 三种描述——切换动画首帧卡（新页首次 build 慢）、点击后明显延迟才开始切（手势/路由层卡）、只有第一次切卡（首次初始化）。**诊断需同时看三条路径**。

### #3 日历页

- **D6 删掉今日信息卡**。
- **D7 格子里显示倒计时**：每天格子里显示「距离下一个岗 X 小时」这类信息，取代原来的班次胶囊 + 农历那套布局。

### #4 排班制（多班组错开）

- **D8 一个班 = 2h 值 + 8h 休（10h 一组），一天多班组轮转**。
  - 5 个班组、班组间错开 2h、初始时段为 0/2/4/6/8h。
  - Day 1：第一班 0-2、10-12、20-22（3 班）；第二班 2-4、12-14、22-00；第三班 4-6、14-16；第四班 6-8、16-18；第五班 8-10、18-20。
  - 下一个班组第一班开始时间 = 前一个班组最后班结束时间 + 8h。
  - **稳定周期 2 天**（Day 4 与 Day 6 相同，之后无限循环）；启动阶段 Day 1~3 各不相同。
  - 24h 恰好 12 个 2h 时段，5 班组均分：3 班组盖 3 班、2 班组盖 2 班（或反之），总和永远 12。
- **D9 用时间名取代白班夜班**：时段名从「白 / 夜」这种改成「0-2」「10-12」这种时间段（数据里本就有 `startMinute`/`endMinute`）。

### 版本与上版处置

- **D13 上版 N3（排班多选）保留代码不撤**（两个提交 `55b3fac` + `54fa021` 与本次 #4 不冲突）。

- **D15 上版决策记录 `decisions-salary-nav.md` 归档**，本版决策记录就这份。

### #5 tab 开关与排序

- **D16 关掉 tab = 隐藏 + 相关提醒不再新做、历史数据保留**（用户采纳）。
  - 闹钟：关掉时保留现有闹钟不删，但排班结构变了不再重排（`rescheduleAll` 早退）。
  - 待办：关掉时保留现有待办，重复待办生成停止（`skipRecurringOccurrence` 早退）。
  - 日历 / 我的 / 薪资：无后台，纯隐藏。
- **D17 关掉时弹一次确认**（「关掉后不会再排新闹钟，历史闹钟保留，确定？」）。
- **D18 排序**：支持拖拽重新排序底栏 tab（用户原需求「可以关闭某一导航栏页面也可以进行排序」）。

### #6 系统日历同步

- **D19 单向**：App → 系统日历（用户采纳）。
- **D20 时机**：每次排班变更自动推（与用户原话「直接同步」一致）。
- **D21 范围**：未来 60 天（覆盖日常查看 + 同步性能可控）。
- **D22 冲突处理：幂等标记**（App 端存 id → eventId 映射，增量更新，不产生大量「删建」痕迹）。
- **D23 vivo 适配**：用户选目标 Calendar Provider（首次弹一次）+ vivo 机型额外提示「若同步不成功请到系统设置 → 权限管理 → 日历白名单里允许本应用」；**不硬编码 vivo 私有 API**，走标准 `CalendarContract`。
- **D24 插件**：用 `device_calendar_plus`（bullet.to 官方维护、标准 API、活跃）。

### #3 日历页倒计时（格式全部拍板）

- **D25 倒计时只在今天那格显示**（不展示“明天距”这种无意义的长时间倒计时）。
- **D26 非“今天”的格子显示**：日期 + 岗次数 + 首末时段（“15 号 / 3 岗 · 0-2→20-22”）。首末时段隐含中间岗（因为都是 2h+8h 循环）。
- **D27 倒计时分段精度**：< 1h 用分钟（“距 45min”），≥ 1h 用小时（“距 2h”）。
- **D28 当天所有岗都过完 → 切静态**（日期 + 岗次数 + 首末时段，跟非今天那格一致，不额外造“今天已过”文案）。

## #3 续：日历格子可读性（2026-10-24 拷打第二轮，强度 4 深挖）

> 背景：用户拿到 10-24 12:45 的 debug 包后报「日历页面里面的岗次都挤到一起了根本看不清」。
> 强度 4（深挖），决策续记本文件。

### 已查明（事实，自查）

- 用户手里的包确实是新 3 行布局（10-23 17:03 的 release 包还是旧布局，10-24 12:45 的 debug 包已含 #3）——用户截图核对无误：每格「日期 + N岗 + 首末时段串」。
- 「看不清」的机制：第 2 行首末时段串（"22-23→16-18"，11 字符）约 66dp，格内容宽只有 ~43dp（360dp 屏 / 7 列），外层**整格** `FittedBox scaleDown` 把全部行等比缩到 ~0.7 —— **日期被时段连带缩小**（`calendar_screen.dart:1948`）。
- 点一天目前**没有任何反应**：信息卡删除后 `_selected` 只剩液态玻璃块在用。
- `_infoCard`（完整版 + 小窗紧凑版）已无调用点 = **死代码**（约 430 行），连同其专属徽章/班组/统计辅助件。
- 宽横屏右栏 `_sideRail` 现返回空 `SizedBox.shrink()`（`:908`）—— 280~340dp 的空白栏；小窗（`isShort`）网格整块不画（`if (!layout.isShort) grid`）→ 只剩顶栏。#3 的两处遗留半成品。
- 快照 v3 已带每格 `shifts`/`shiftsOverflow`，Kotlin 渲染侧**未消费** —— 月历卡仍每格一颗简称胶囊（54fa021 只落了数据没落渲染）。

### 决策（本轮新增，接续 D32）

- **D33 第 2 行改「起始钟点串」**：多岗次画 "8·12·20"（各岗次开始钟点、不带前导零、`·` 分隔），单岗次保持 "8-20"。比首末时段串短四成以上，且中间岗次可见（首末串隐含中间岗的前提对 2h+8h 成立，但读不出来）。当天岗次全部过完 → 切静态同款（D28 语义不变）。
- **D34 每行独立缩放（订正）**：截图证实行级独立缩放**已存在**（三行各自包 `FittedBox`，外层整格 `FittedBox` 只在极端矮格扈高度）——「挤到一起」的真正机制是**第 2 行长串（11 字符）被自己的行级 `FittedBox` 缩到贴边**（左右余量≈0，日期行没缩）。所以本轮把行 2 从「长串被缩到 ~0.65 贴边」改成「短串自然字号」（D33 即是修复）；外层整格 `FittedBox` **保留**为高度兜底；护栏断言改为「行 2 在字号档 1.2 × 320/360 下不被缩」（原计划「拆外层」作废）。今天格倒计时规则不变（D25~D29）。
- **D35 点格子 → 底部弹层（当天详情）**：当天全部岗次（起止钟点 + 进行中/已过/未到状态）+「其他班组」一行（死代码里那块的唯一归宿）；**无班日不弹**；调班入口维持长按不变（v0.11.16 长按「调整班次」弹层）。
- **D36 宽横屏右栏 = 选中日详情栏**：与弹层**共用同一个内容件**，点日期右栏即更新；不再空白。小窗（`isShort`）**恢复画网格**（删 `if (!layout.isShort)` 条件——当初删网格的理由是「信息卡会挤压网格」，信息卡已删，理由消失），点格子走同一弹层。
- **D37 详情底部放次要按钮「调整这天」** → 进调班弹层；长按入口照旧保留，两条不冲突。
